# QA C8-03 — Alta manual de pedidos

Estado: completado localmente — 2026-08-09.

## Objetivo

Permitir que un administrador registre un pedido recibido por WhatsApp sin confiar en precios o nombres enviados por el navegador. El servidor resuelve el catálogo vigente y persiste snapshots en una transacción.

## Criterios

- [x] Solo un admin autenticado puede crear pedidos.
- [x] El endpoint exige al menos una línea con `productId` válido.
- [x] Producto archivado, no publicado o no disponible es rechazado.
- [x] Nombre y precio se toman del catálogo server-side.
- [x] Modificadores se validan contra los grupos y opciones del producto.
- [x] Producto con grupo obligatorio incompleto es rechazado.
- [x] El pedido inicia en `RECEIVED`.
- [x] Se crea el evento inicial con actor y motivo.
- [x] Total, ajuste y subtotal quedan persistidos.
- [x] Pedido y evento se crean juntos.
- [x] C7 no presenta regresiones.
- [x] Tests, audit y build pasan.

## Implementación

- Servicio: `src/modules/orders/service.ts`.
- Endpoint: `POST /api/admin/orders`.
- Tests: `src/modules/orders/service.test.ts`.
