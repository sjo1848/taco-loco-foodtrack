﻿UI-002 — BLUEPRINT VISUAL EJECUTABLE DE PANTALLAS
Taco Loco Foodtrack
CuyoConsulting and Development
Fecha: 08/08/2026
Estado: DEFINIDO COMO BASE DE EJECUCIÓN VISUAL — render editable pendiente


1. PROPÓSITO
Convertir UI-001 en especificaciones de pantalla suficientemente concretas para que Penpot, otro diseñador o el futuro frontend puedan materializar la UI sin tomar decisiones estructurales nuevas. Este documento no reemplaza la revisión visual final ni cierra por sí solo Fase 4.


Fuentes canónicas: UX-001, UI-001, MEN-001, ALC-001 y PRE-DEV-002.


2. REGLAS GENERALES
- Mobile-first.
- Referencia móvil principal: 390 px.
- Margen lateral general: 16 px.
- Escala de espacios: 4/8/12/16/24/32.
- Touch target mínimo: 44×44 px.
- Botón principal: mínimo 48 px de alto.
- Tarjetas: Radius/Card 16 px.
- Fondo público: Brand/Background #0E0E0D.
- Superficies: Brand/Surface #181714 y Surface-2 #211F19.
- Texto principal público: Brand/Cream #F5E8C8.
- Acentos de marca: verde, rojo y amarillo con uso moderado.
- No usar sombras fuertes, glassmorphism, neumorphism ni gradientes decorativos innecesarios.


3. UI-PUB-01 — MENÚ PÚBLICO MOBILE 390
Frame: 390 px de ancho. Alto variable según contenido.


3.1 Header
- ancho 100%;
- padding horizontal 16 px;
- padding vertical 12–16 px;
- altura objetivo aproximada: 76–92 px;
- logo/mascota: 52–64 px de alto máximo;
- slogan opcional en UI/Caption o UI/BodySmall;
- no usar hero completo ni imagen de fondo dominante.


3.2 CategoryNav sticky
- posición sticky debajo del header;
- alto visual aproximado: 52–56 px;
- padding horizontal 16 px;
- gap entre chips: 8 px;
- CategoryChip alto: 36–40 px;
- padding horizontal: 14–16 px;
- Radius/Pill;
- scroll horizontal sin wrap;
- chip activo con un único acento dominante y contraste suficiente.


3.3 Destacados
- margen superior 24 px;
- título Display/Category;
- máximo 1–2 tarjetas visibles como propuesta inicial;
- no carrusel obligatorio;
- si no hay featured, toda la sección desaparece sin dejar espacio.


FeaturedProductCard de referencia:
- ancho disponible: 358 px;
- padding: 16 px;
- imagen superior o lateral solo si aporta valor;
- precio siempre visible en primer bloque de lectura;
- no introducir CTA de compra dentro de la tarjeta.


3.4 Sección de categoría
- margen superior entre categorías: 32 px;
- heading: Display/Category 26 px;
- gap heading→primer producto: 12–16 px;
- gap entre ProductCards: 12 px.


3.5 ProductCard principal
Ancho de referencia: 358 px.
Padding interno: 12 px.
Radio: 16 px.
Borde: 1 px Brand/Border o diferenciación tonal equivalente.
Altura mínima recomendada: 124–132 px cuando hay imagen.


Layout horizontal:
- bloque de contenido flexible a izquierda;
- gap: 12 px;
- imagen opcional: 104×104 px como referencia, rango permitido 96–112 px;
- imagen con radio 12 px y object-fit cover;
- nombre: UI/ProductName 18 px semibold;
- descripción: UI/BodySmall 14 px, 2–3 líneas preferidas;
- metadata de modificador: UI/Caption 12 px;
- precio: UI/Price 20 px bold;
- precio y nombre no deben quedar ocultos por truncamiento visual.


Producto sin imagen:
- conservar mismo padding y jerarquía;
- aprovechar ancho completo para texto;
- no mostrar placeholder decorativo obligatorio.


Producto agotado:
- tarjeta sigue visible;
- badge “Agotado” cerca de nombre o precio;
- imagen puede usar opacidad reducida;
- nombre y precio mantienen contraste suficiente;
- no bajar la opacidad del card completo a un nivel que perjudique lectura.


3.6 SaucesInfo
- bloque compacto en Surface-2;
- padding 12–16 px;
- texto: “Salsas disponibles: Guacamole · Cheddar · Criolla · Picante · Roquefort”;
- puede incluir una imagen del flyer solo como apoyo, no como requisito.


3.7 WhatsAppCTA
Mobile:
- barra/área persistente inferior;
- padding lateral 16 px;
- padding superior/inferior suficiente para safe-area;
- botón interior altura mínima 52 px;
- ancho útil completo;
- icono + “Pedir por WhatsApp”;
- alto contraste;
- reservar padding-bottom en el contenido para que nunca tape la última tarjeta.


4. UI-PUB-02 — ESTADOS PÚBLICOS
Loading: skeletons simples o indicadores discretos, sin bloquear marca y estructura.
Error: mensaje claro + botón “Reintentar”.
Menú vacío: mensaje explícito, sin simular productos.
Sin imagen: layout funciona sin placeholder obligatorio.
Sin destacados: sección inexistente.
Agotado: ver 3.5.


5. UI-ADM-01 — LOGIN MOBILE
Frame: 390 px.
Fondo: crema/gris muy claro.
Contenedor principal:
- margen horizontal 20–24 px;
- card de 342–350 px aprox.;
- padding 24 px;
- radio 16 px;
- contenido en una columna.


Orden:
1. logo pequeño 48–56 px;
2. título “Administración Taco Loco”;
3. campo email/usuario;
4. campo contraseña;
5. error inline cuando corresponda;
6. botón “Ingresar” altura 48–52 px.


Gap entre campos: 16 px.
Labels visibles, no depender solo de placeholders.


6. UI-ADM-02 — PRODUCTOS MOBILE
Frame: 390 px.
Padding lateral: 16 px.


Header:
- AdminHeader compacto;
- título “Productos”;
- acción “Nuevo producto”.


Herramientas:
- búsqueda administrativa simple;
- filtro de categoría;
- gap 8–12 px;
- apilados verticalmente si el ancho no permite una fila cómoda.


ProductAdminCard:
- padding 12–16 px;
- radio 14–16 px;
- nombre + categoría;
- precio visible;
- thumbnail opcional 56–64 px;
- toggle Disponible/Agotado con target >=44 px;
- acción “Editar” claramente separada;
- el toggle no debe confundirse con navegación a edición.


Pending toggle:
- deshabilitar temporalmente interacción repetida;
- feedback visual de guardado.
Error toggle:
- restaurar estado previo o mostrar error inequívoco según implementación posterior;
- UI debe reservar espacio para feedback.


7. UI-ADM-03 — EDITAR PRODUCTO MOBILE
Frame: 390 px.
Padding lateral: 16 px.
Formulario: una columna.


Secciones con separación 24–32 px:
A. Información.
B. Precio.
C. Imagen.
D. Estado.
E. Opciones/modificadores.
F. Orden.


Inputs:
- alto mínimo 44–48 px;
- radio 12 px;
- label visible;
- helper/error debajo del control;
- focus visible.


ImageUploader:
- zona de carga clara;
- preview cuando exista imagen;
- estados uploading/error;
- no requerir imagen para guardar un producto si el modelo no la exige.


Acciones finales:
- Guardar: primario, 48–52 px;
- Cancelar/volver: secundario;
- separación suficiente entre acciones;
- saving, success y error contemplados.


8. UI-KIT — DIMENSIONES BASE
CategoryChip: 36–40 px alto.
Primary Button: 48–52 px alto.
Input: 44–48 px alto.
Toggle: target total >=44×44 px.
AvailabilityBadge: mínimo 24–28 px alto con texto.
Product image: 104×104 px de referencia.
Admin thumbnail: 56–64 px.
Public card radius: 16 px.
Admin card radius: 14–16 px.


9. RESPONSIVE REPRESENTATIVO
Breakpoints exactos quedan para Fase 5/front-end; UI define comportamiento, no framework.


Tablet:
- max-width de contenido aproximado 720–840 px;
- catálogo puede pasar a 2 columnas si las descripciones siguen legibles.


Desktop:
- contenedor público centrado, max-width aproximado 1120–1200 px;
- catálogo puede usar 2 o 3 columnas según densidad;
- no cambiar el orden semántico por categorías;
- CTA WhatsApp puede ser botón persistente discreto lateral/inferior;
- admin puede usar 2 columnas en formulario, manteniendo agrupaciones.


10. QA VISUAL PREVIO A CIERRE
PASS requerido:
- ningún precio necesita zoom;
- ningún CTA principal menor a 44 px táctiles;
- focus visible en controles;
- Agotado incluye texto;
- error incluye texto y recuperación cuando aplica;
- WhatsApp no tapa contenido;
- ProductCard funciona con y sin imagen;
- Public Menu funciona sin Destacados;
- admin permite disponibilidad desde listado;
- edición separada mantiene agrupaciones;
- mobile sigue siendo la referencia principal.


11. DECISIÓN DE FASE
Con UI-001 + UI-002 quedan definidas las decisiones visuales estructurales y las medidas base suficientes para ejecutar los mockups sin nueva fase de análisis. Fase 4 permanece EN PROGRESO hasta que los mockups editables principales y el UI Kit sean materializados y revisados visualmente.


No se habilita construcción todavía.
