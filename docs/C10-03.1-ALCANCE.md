# C10-03.1 — Semántica y trazabilidad de intención

Estado: IMPLEMENTADO — pendiente de CI y revisión — 2026-08-10  
Origen: `REV-C10-XPROD-001` de Drive  
Tipo: corrección de coherencia antes del cierre de C10

## Hipótesis

Si distinguimos una intención creada desde el menú web de un pedido originado realmente por WhatsApp, la administración podrá interpretar correctamente los registros y el proyecto quedará preparado para medir conversión sin confundir intención con confirmación.

## Alcance

- ampliar `OrderSource` con `PUBLIC_MENU`;
- registrar las intenciones públicas con `source = PUBLIC_MENU`;
- conservar WhatsApp como canal de continuación, no como origen estructurado de la intención;
- mostrar en la bandeja una señal explícita: `Menú web · WhatsApp pendiente`;
- mantener `RECEIVED` como estado inicial, sin confirmar disponibilidad ni pedido;
- documentar una política manual para intenciones abandonadas durante el piloto;
- agregar pruebas de source, idempotencia y copy administrativo.

## Fuera de alcance

- cron o expiración automática;
- nuevo estado `ABANDONED`;
- webhook, bot o lectura de WhatsApp;
- tracking del cliente;
- pagos, stock reservado o integración con UspaYa.

## Criterios de aceptación

- [ ] Una intención creada desde el menú persiste `source = PUBLIC_MENU`.
- [ ] Los pedidos manuales existentes conservan `WHATSAPP` por compatibilidad con el MVP actual.
- [ ] Las intenciones repetidas mantienen idempotencia por `clientReference`.
- [ ] La bandeja distingue una intención pública pendiente sin alterar sus acciones de estado.
- [ ] El detalle conserva la nota de seguimiento y muestra el origen de forma consistente.
- [ ] La migración es aplicable sobre una base existente sin perder pedidos.
- [ ] Typecheck, lint, tests, audit y build pasan.

## Decisión de cierre

C10-03.1 se aprueba cuando la semántica estructurada, la visualización administrativa y las pruebas quedan alineadas. Luego se puede iniciar C10-04 como cierre visual acotado.
