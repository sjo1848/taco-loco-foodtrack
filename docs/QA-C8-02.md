# QA C8-02 — Transiciones y auditoría

Estado: completado localmente — 2026-08-09.

## Objetivo

Centralizar el cambio de estado en una transacción server-side que valide la máquina de estados, actualice el pedido y cree un evento de auditoría en la misma operación.

## Criterios

- [x] Pedido inexistente devuelve `ORDER_NOT_FOUND`.
- [x] Transición inválida devuelve `INVALID_ORDER_TRANSITION`.
- [x] Cancelación sin motivo devuelve `CANCELLATION_REASON_REQUIRED`.
- [x] Cambio concurrente se protege con actualización condicional por estado.
- [x] Confirmación guarda `confirmedAt`.
- [x] Entrega o cancelación guarda `closedAt`.
- [x] Cada transición crea un `OrderEvent` con actor, estado anterior, nuevo estado, fecha y motivo.
- [x] La actualización y el evento se confirman o fallan juntos.
- [x] Tests, audit y build pasan.

## Implementación

- Servicio: `src/modules/orders/service.ts`.
- Modelo de transiciones: `src/modules/orders/model.ts`.
- Tests unitarios: `src/modules/orders/service.test.ts`.
